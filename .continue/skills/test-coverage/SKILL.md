# テストカバレッジ・チェック

新しい機能には適切なテストカバレッジが必要です。

## テストが必要な場合

1. **新しくエクスポートされた関数またはクラス** - コードベースの他の部分で使用される、新しくエクスポートされた公開関数、クラス、またはモジュールには、少なくとも以下の内容をカバーする基本的なユニットテストが必要です：

   - ハッピーパス（期待される入力が期待される出力を生成する）
   - エッジケース（空の入力、null/undefined、境界値）
   - エラーケース（無効な入力が適切なエラーをスローまたは返す）

2. **新しい CLI コマンドまたはサブコマンド** - 以下が必要です：

   - コマンドが登録され、実行されることを検証するスモークテスト
   - フラグの解析とバリデーションのテスト
   - 期待される出力形式のテスト

3. **バグ修正** - PR がバグを修正する場合、以下の内容を含む回帰テストが必要です：

   - 元のバグの状態を再現する
   - 修正によって解決されることを検証する

4. **新しい API エンドポイントまたはハンドラー** - 以下をカバーする統合テストが必要です：
   - 成功したリクエスト/レスポンス
   - 無効な入力に対するエラーレスポンス
   - 認証/認可（該当する場合）

## テストが不要な場合

- ドキュメントのみの変更
- 設定ファイルの変更 (YAML, JSON, Markdown)
- CSS/スタイリングの変更
- 依存関係の更新 (動作を変更しない場合)
- エージェント定義ファイル (`.continue/agents/*.md`)
- 動作を変更しないリファクタリング (既存のテストが引き続きパスする場合)
- 既存のテストですべてカバーされている内部実装の変更

## テストインフラリファレンス

- **Core**: Jest (`*.test.ts`) + Vitest (`*.vitest.ts`) in `core/`
- **GUI**: Vitest (`*.test.ts`) in `gui/src/`
- **CLI**: Vitest (`*.test.ts`, `*.e2e.test.ts`) in `extensions/cli/`
- **Packages**: Vitest in each `packages/*/` directory
